= image-readonly-appliance

== Read-only root, MBR

Forked from `image-rpios` (`image/mbr/simple_dual`). Same MBR/vfat-boot/ext4-or-btrfs-root
layout, but root and boot are mounted `ro` by default instead of `rw`, and
`/run`, `/dev/shm` and `/sys/fs/cgroup` are tmpfs.

Unlike `image-rota` (`image/gpt/ab_userdata`), this uses MBR, not GPT, so it
works on any Raspberry Pi model, including those without GPT boot support
(Pi 1/2/3, original Pi Zero). It does not provide A/B slots or OTA update
support - if you need those and your target hardware is Pi 4/CM4/Pi 5/CM5,
use `image-rota` instead.

[cols="1,3,1,4", options="header"]
|===
| Mount point | Backing | Type | Notes

| / | /dev/disk/by-slot/system | ext4 or btrfs | ro
| /boot/firmware | /dev/disk/by-slot/boot | vfat | ro
| /run, /dev/shm, /sys/fs/cgroup | tmpfs | tmpfs | rw, volatile
| /data | third physical partition, BTRFS (dup) | btrfs | rw, persistent - created on first boot by layer `data-partition`, absent from the built image
|===

This layer only sets up the read-only mount points. Combine with:

* `setup-tmpfs` - zram-backed `/var/log` and `/tmp`, so nothing needs to
  write to the read-only root during normal operation.
* `data-partition` - non-interactively grows root to a fixed size and
  creates the BTRFS `/data` partition from whatever space remains on the
  physical disk, on first boot.
* `readonly-root` - disables services that assume a writable root, ships
  `ro`/`rw` helper commands, and points logrotate/chrony/fake-hwclock state
  at `/data`.
* `hostname-from-mac` - optional, sets the hostname from the first MAC
  address found, once, on first boot.

See `config/homegear-readonly-appliance-trixie.yaml` for a complete example.
